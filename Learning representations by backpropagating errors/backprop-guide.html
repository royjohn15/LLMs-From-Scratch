Implementation Guide

Backprop From Scratch

A build order for a complete, testable neural-network framework in NumPy — and for using it to reproduce the experiments in Rumelhart, Hinton & Williams (1986), Learning representations by back-propagating errors.

Read this part before writing a line

Three decisions come first, because getting them wrong costs a rewrite rather than an edit.

1 — Fix your notation and never change it

Your PDF notes already commit to a scheme: layers k = 0…L, activation xi(k), pre-activation zj(k+1), weight wij(k) running from unit i of layer k to unit j of layer k+1. The 1986 paper uses xj for total input and yj for output — the exact opposite of your x. Pick yours, write the translation table into a docstring at the top of the package, and read every paper equation through it. Most "my gradient is wrong" bugs at this stage are actually a notation slip.

2 — Extract the spec into a checklist

The paper is the spec. Before coding, write out every architecture, count, and hyperparameter you intend to reproduce (the table further down is a starting point) and keep it as SPEC.md. At the end, each line gets ticked against a number your code actually printed — not against a plot that looks about right.

3 — Settle the implementation forks now

NumPy float64 arrays, batch-as-rows (X is n_cases × n_units), no autograd, no PyTorch, no classes deeper than one level of inheritance. Matplotlib only inside viz.py so the core stays dependency-light. Sigmoid units everywhere by default, since that is what the paper uses and what its results depend on.

The four equations everything else serves

Written in your notation, for the squared-error measure of the paper: E = ½ Σc Σj (xj(L) − yj)², summed over cases c and output units j. Teal is the forward pass, rust the backward pass — keep that colour split in your own diagrams and log output, it makes wiring errors visible.

Forward — pre-activation
zj(k+1) = Σi wij(k) xi(k) + bj(k)
The only place the weights are used in the forward direction. Cache x(k) here — the backward pass needs it.
Forward — activation
xj(k+1) = φ(zj(k+1)),  φ(z) = 1 / (1 + e−z)
Cache the output, not the input: the logistic derivative is φ′ = x(1 − x), cheaper from the output.
Backward — delta recursion
δj(L) = (xj(L) − yj) φ′(zj(L))
δi(k) = (Σj wij(k) δj(k+1)) φ′(zi(k))
δ is ∂E/∂z. The recursion is the whole paper: the error signal for a hidden unit is the weighted sum of the error signals it feeds.
Backward — parameter gradients
∂E/∂wij(k) = xi(k) δj(k+1)
∂E/∂bj(k) = δj(k+1)
A bias is just a weight from a unit clamped at 1 — implement it that way in your head, separately in code.

The update rule the paper actually recommends is steepest descent with the momentum term, applied after gradients have been accumulated over all cases in the sweep:

Δw(t) = −ε · ∂E/∂w(t) + α · Δw(t−1)        ε = learning rate, α = momentum (0.9 in the paper)

The matrix forms you will actually write, with rows as cases:

Z = X @ W + b                    # X: (n, in)   W: (in, out)   Z: (n, out)
dX = dZ @ W.T                    # error signal handed to the previous layer
dW = X.T @ dZ                    # summed over the batch automatically
db = dZ.sum(axis=0)

Note that X.T @ dZ already sums the gradient over cases, which is exactly the paper's batch ("sweep") mode. Per-case (online) mode is the same code with n = 1 — do not write two implementations.

The shape of the framework

One rule makes the rest fall out: every layer is an object that knows how to run forwards, how to convert an incoming ∂E/∂output into an outgoing ∂E/∂input, and which parameters it owns. Weight sharing, recurrence, and gradient checking all become easy once parameters are objects passed by reference rather than raw arrays.

class Parameter:            # value + gradient buffer, shared by reference
    value: np.ndarray       # float64
    grad:  np.ndarray       # accumulated, zeroed explicitly by the trainer

class Layer:
    def forward(self, x)  -> out      # caches whatever backward needs
    def backward(self, g) -> g_in     # ACCUMULATES into p.grad, returns dE/dx
    def parameters(self)  -> [Parameter]

class Loss:
    def forward(self, pred, target) -> float
    def backward(self)              -> dE/dpred

class Optimizer:                       # SGD(params, lr, momentum)
    def step(self); def zero_grad(self)

The one non-obvious design choice

Make activations their own layers rather than a flag on Dense. It doubles the number of objects in a network and removes an entire class of bugs — the φ′ factor can then only ever be applied in one place, and you can gradient-check the linear map and the nonlinearity independently.

Build order

Each phase ends with something you run and read. Do not start a phase until the previous phase's check has printed the number it promised — an unverified layer under a verified trainer wastes the whole stack.

01

Derive the equations by hand, on paper

Take a 2–2–1 sigmoid network with biases and write out ∂E/∂w for one hidden-to-output weight and one input-to-hidden weight, fully expanded. This is the content of the paper; everything after is bookkeeping.

Done when
You can reproduce the delta recursion without looking, and your symbols match the ones in your PDF notes.
02

Scalar prototype — loops, no vectorisation

One file, ~120 lines, explicit Python loops over units and weights, hard-coded to one hidden layer. Train it on XOR (2–2–1). Slow and ugly is the point: it is the reference implementation you will check the fast one against.

Done when
XOR error falls below 0.01 within 5,000 sweeps for at least 4 of 5 random seeds, and you print the seed that fails.
03

The gradient checker — before anything else

Two-sided finite differences: perturb one parameter by h = 1e−5, recompute the loss both ways, compare (E₊ − E₋)/2h with your analytic gradient using relative error |a−n| / max(|a|,|n|,1e−12). Run it over every parameter of a small net, biases included.

This is the single highest-value component in the project. Every later phase is verified by it, which is why it comes third rather than last.

Done when
Max relative error over all parameters of the loop prototype is below 1e−7 in float64, and deliberately breaking one term (drop φ′, transpose W) makes the check fail loudly.
04

Parameter and Dense, vectorised

Now write the real Dense layer against the matrix forms above. Gradients accumulate into p.grad (+=, never =) — this is what later makes tied weights and multi-input nets work for free.

Done when
Dense passes gradcheck standalone, and its gradients match the loop prototype's to 1e−12 on identical weights and inputs.
05

Activations and losses as separate modules

Sigmoid (with the x(1−x) derivative from the cached output), Tanh, Identity. Losses: the paper's sum-of-squares halved, plus mean-squared and cross-entropy for later comparison. Keep the sum-vs-mean distinction explicit in the class name — it silently rescales your learning rate.

Done when
Each activation and each loss passes gradcheck on its own, and SumSquaredError on the XOR set equals your hand-computed value for one fixed weight vector.
06

Network container

Sequential: forward through the list, backward through the reversed list, parameters() flattening every layer's, zero_grad(). Nothing clever. Add a summary() that prints layer shapes and total parameter count — you will use it in every experiment write-up.

Done when
A 3-hidden-layer net with mixed activations passes end-to-end gradcheck, and summary() parameter counts match a hand calculation for the symmetry net (6–2–1 → 17 parameters).
07

Initialisation and symmetry breaking

Uniform random in (−r, r) with r small (the paper uses small random weights; 0.3–0.5 works). Route every draw through one seeded np.random.Generator stored on the experiment, never the global one.

Then reproduce the failure the paper warns about: initialise all weights identically and watch hidden units stay identical forever. Keep it as a test — it is a result, not an accident.

Done when
Two runs with the same seed produce bitwise-identical weights, and the all-equal-init XOR run is asserted to stay above 0.2 error after 5,000 sweeps.
08

Optimiser: steepest descent, then momentum

Implement plain w ← w − ε·∂E/∂w first and confirm it learns XOR. Then add the momentum recurrence exactly as written in the paper — store Δw(t−1) per parameter, and be careful that ε multiplies only the gradient term.

Done when
Three hand-computed momentum steps match your optimiser to 1e−12, and batch-mode gradients equal the sum of per-case gradients to 1e−12 (assert it — this is the sweep/online equivalence the paper relies on).
09

Trainer, history, reproducibility

A train() that takes a net, task, optimiser, sweep count, and mode (batch / minibatch / online); logs error per sweep plus whatever the task calls "correct"; and writes results/<experiment>_<seed>.npz with history, final weights, and the full config dict. Every experiment must be re-runnable from that config alone.

Done when
A run reloaded from its .npz reproduces the same final error, and the config dict contains the seed, ε, α, architecture, and sweep count.
10

Instrumentation

Three plots, and no more for now: error-vs-sweeps curves (several seeds overlaid), a Hinton-style diagram of a weight matrix (square area ∝ |w|, filled/hollow by sign — this is how the paper shows its learned weights), and a hidden-activity matrix of all cases × hidden units. The last two are how you will read the representations rather than just score them.

Done when
The Hinton diagram of a trained XOR net is legible enough that you can state each hidden unit's function from the picture alone.
11

Experiment: symmetry detection

Six input units, two hidden, one output; all 64 binary patterns; target 1 if the pattern is symmetric about its centre. Train with batch sweeps. The result to reproduce is not the error curve but the structure: weights from the input to each hidden unit come out in ratio 1 : 2 : 4 in magnitude, with mirror-image positions carrying opposite signs, so the two halves cancel exactly when — and only when — the pattern is symmetric.

Done when
You print the 6×2 input-to-hidden matrix and assert the ratio and antisymmetry programmatically (within tolerance), for at least 3 of 5 seeds. A run that merely reaches low error has not reproduced the figure.
12

Experiment: family trees

The centrepiece, and the reason the paper is titled "learning representations". Two structurally isomorphic family trees (English and Italian), 24 people, 12 relations, 104 valid (person1, relation) → person2 triples. The architecture is not a plain stack — two separate one-hot inputs each go through their own small encoding layer, meet in a central layer, then pass through a decoding layer to the 24-way output. Build it, hold out four triples, train the rest, and then look at the person-encoding units.

What you are checking is that the encoding units come to represent nationality, generation, and branch of the family — features nobody put in the data, which exist only because they make the task easier.

Done when
You can name what at least three encoding units represent from the activity map, and the held-out triples are answered correctly (report the exact count out of 4, over several seeds — the paper's generalisation claim is a small number and should be reported as one).
13

Experiment: the 8–3–8 encoder

Eight one-hot inputs, three hidden units, reconstruct the input. The hidden layer is forced to discover a binary code. Cheap to run, and it is the clearest demonstration in the whole project that hidden units are a learned representation rather than a fitting device.

Done when
All 8 patterns are reconstructed correctly and the 8×3 hidden-activity table, rounded, contains 8 distinct binary codes.
14

Recurrent nets by unfolding, with tied weights

The paper's final move: a recurrent network is a layered network in which corresponding layers share weights. Implement TiedDense — several layers holding the same Parameter objects. Because your gradients accumulate rather than assign, unrolling T steps and calling backward once already sums the gradient over time steps; the constraint is satisfied for free. Test on a small sequence task (parity of a bit stream, or completing a repeating sequence).

Done when
An unrolled tied net passes gradcheck (the strongest possible test that sharing is correct), and its accumulated gradient equals the sum of the per-step gradients of an untied net with identical weights.

The bugs you will actually hit

  • Updating weights inside the backward pass. Deltas for layer k must be computed with the old w(k). Compute all gradients, then step.
  • Missing φ′ at the output layer. With squared error and sigmoid outputs the output delta still carries x(1−x). Dropping it happens to still train, slowly — which is why only gradcheck catches it.
  • Sum vs mean loss. A loss averaged over n cases scales every gradient by 1/n, so ε from the paper no longer means what it meant. The paper sums.
  • Forgetting to zero gradients between sweeps. Accumulation is deliberate; zeroing must be too.
  • Transposed weight matrix in the backward pass. dX = dZ @ W.T, not W @ dZ. Shape errors catch most cases; square layers hide it.
  • Saturated sigmoids from large initial weights. Gradients vanish and the net never leaves its initial state — looks like a broken optimiser.
  • Global RNG. One np.random call somewhere unseeded makes every "reproducible" run a lie.
  • Symmetry between hidden units. Equal initial weights, or accidentally sharing one array across layers by assignment instead of copy.
  • float32. Gradient checking needs float64; mixing precision makes the relative-error threshold meaningless.

If you only do three things

  • Write the finite-difference gradient checker in phase 3, not at the end. Everything else in the project is verified by it.
  • Make gradients accumulate into shared Parameter objects. Weight sharing and recurrence then cost you nothing.
  • Judge the experiments by the structure of the learned weights and hidden activities, not by the error curve. The claim of the paper is about representations; an error curve does not test it.
